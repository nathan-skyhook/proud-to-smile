### Reference-site quirks worth noting (do not replicate literally)

- Several primary nav links are broken/malformed in the source markup: `Doctors` (`https:///doctors`), `Find Location` (`https:///locations`), `Patient Portal` (`https:///patient-portal`), and `Schedule Appointment` (`https:///schedule-appointment`) all resolve to a protocol-relative URL missing its host. The pages themselves are live (confirmed via sitemap + direct fetch); only the anchor `href` is malformed. Build real, correctly-formed links for these in Proud to Smile.
- The top utility bar contains two placeholder links literally labeled "Demo Link #1" and "Demo Link #2" — template cruft, skip.
- "Pay Online" in the header currently links out to `https://www.google.com` (placeholder) rather than the real `/bill-pay/` page, which is why the crawler couldn't reach it via nav — `/bill-pay/` exists and is real content, just orphaned in the nav.
- `/smile-gallery`, `/testimonials`, `/offers-promotions` are real, fully-built pages but are not linked from header or footer navigation on the reference site (orphaned demo content). Per BUILD_ALL they should still be rebuilt, just without a corresponding nav entry unless the client wants them added.
- Most page `<title>` tags read like `"X - General"` — an unconfigured Yoast SEO variable (site "category"/type placeholder never renamed to the practice name). Do not carry the literal string "General" into Proud to Smile's titles.
- The footer copyright reads "© 2026 Practice Name. All rights reserved." — an unreplaced template token. Replace with the real Proud to Smile business name/year.
- Location data (addresses, phone numbers) are placeholder Arizona addresses (Glendale/Tempe, AZ) despite doctor bios and page copy referencing "Chandler" and "Harrison, OH" inconsistently — the demo mixes several city names. Use the client's real location data.

## Design Patterns

### Layout Types

- **Homepage:** Full-bleed hero with two-column content/image split, followed by a stack of full-width `<section>` blocks alternating white and tinted backgrounds (see exact section order below).
- **Service pages (interior, 15x):** Hero banner → intro copy → sub-service anchor list (in-page jump links, e.g. `#porcelain-veneers`) → detailed content blocks per sub-service → related-services grid → CTA band. All 15 service pages share one Elementor-style template.
- **Location pages (2x):** Hero with location name/address/hours/map link → "Your Family's Dental Home" welcome copy → "Modern Comfort, Advanced Care" amenities blurb → "Easy-to-find Community Location" copy → full "Discover Quality Dental Care for Every Smile" services grid (same component reused from homepage) → CTA.
- **Doctor/provider pages (18x):** Name + credentials + specialty header → bio paragraphs → Education list → Associations/memberships list → a single embedded patient testimonial → services-grid repeat → CTA. All identical template.
- **About / Patient Center / legal pages:** Simple hero + single-column rich-text content, no repeating card grids.
- **Blog/News index & posts:** Standard WP blog list (card grid with featured image, title, excerpt, "read more") and a single-column article template for posts.
- **Form-related pages:** No native `<form>` element was found in server-rendered HTML on any page (schedule-appointment, patient-portal, bill-pay, patient-center/new-patients all checked). The "Schedule Appointment" and similar CTAs appear to be buttons/links to an external or client-side-only booking widget, not a real HTML form — build Proud to Smile's appointment/contact forms as genuine Astro forms rather than assuming a widget embed.

### Components

- **Header/Nav:** Sticky header, logo left, top utility bar above it (Emergency Services link, Pay Online, Patient Portal, language switcher), primary nav below with mega-menu dropdowns for "Services" (full 15-item list grouped by category) and simple dropdowns for "About" and "Patient Center." Two CTA buttons pinned right: "Find Location" (secondary/outline style) and "Schedule Appointment" (primary filled button).
- **Hero:** Two-column — left: eyebrow-free H1 + paragraph + two CTA buttons + "★★★★★ on Google" trust signal; right: full-bleed lifestyle photo of a patient. Background uses a soft gradient mesh (`sentry-gradient-bg-mesh-hero` class) rather than a flat color.
- **Insurance strip:** Thin full-width band directly under hero, dark navy background, centered one-line text + small CTA button ("We accept all major insurance providers. Am I Covered?").
- **"What Sets Us Apart" 3-col feature block:** icon-less text cards (Meet Our Doctors / Meet Our Team / About Us / Our Locations — actually renders as a 2x2-feeling 3-col-plus-photo layout) each with heading, 2-sentence description, text link with circular arrow icon.
- **Testimonial slider:** Full-width dark card, large decorative quote-mark glyph, centered quote text, attribution line ("Name | context"), slider dots below (only one shown per screenshot capture — carousel controlled by JS).
- **Services grid ("Discover Quality Dental Care for Every Smile"):** 2-column x 7-row grid of cards, each with a service title, 3–8 bullet sub-items (plain text list, not linked individually except via page anchors), and a full-width bordered "Learn More About X" button. This exact grid is reused verbatim on location and doctor pages.
- **4-col icon-card feature block ("Everything You Need for Better Dental Care"):** New Patients / Patient Forms / Insurance / Pricing, each a bordered white card on a tinted mint-green section background, heading + description + arrow link.
- **CTA band (closing):** Centered white rounded card floating on a dark gradient-mesh background, large heading, short paragraph, two buttons (Schedule Appointment primary, Find Location secondary).
- **Footer:** Dark background, thick (16px) light-teal top border. Columns: (1) per-location cards with name/address/phone, (2) Patient Center links, (3) Quick Links, (4) implicit social icons row (Instagram/Facebook/LinkedIn) near top of footer. Bottom bar: copyright + a long inline list of 11 legal-page links separated by "|".
- **Cards:** Consistently white background, subtle/no shadow (`--shadow-cards:none` — flat design, borders do the separating work), border-radius ~10px (`--rounded-cn-md:10px`), generous internal padding.
- **Buttons:** Pill-shaped (`--btn-radius:99px`), height 44px, primary = solid dark navy bg (`--btn-bg-color:#013d5e`) with white text; secondary = white bg, navy text and border; both use a small circular arrow-icon suffix (SVG chevron) baked into the button component.

## Notes

- **Design system is CSS-variable-driven and Tailwind-utility-based** — the reference site exposes clean design tokens (`--color-brand-1..11`, `--rounded-cn-sm/md/lg`, `--btn-*`, `.spt-large/.spb-large` spacing utilities) that map almost directly onto a Tailwind v4 `@theme` block. Recommend mirroring these tokens 1:1 in Proud to Smile's theme rather than re-deriving colors from screenshots.
- **Flat design language:** no drop shadows on cards (`--shadow-cards:none`), borders and generous whitespace do the visual separation instead of elevation. Rounded corners are moderate (10–20px), buttons are fully pill-shaped.
- **One shared "services grid" component is reused three times**: homepage, every location page, and every doctor page. Build it once as a reusable Astro component.
- **All 18 doctor pages and both location pages share one template each** — only copy/images/meta differ. Same for all 15 service pages (identical structure, differs only in sub-service list and body copy) and all 10 blog posts / 10 news posts (standard post templates).
- **No native HTML forms exist anywhere on the reference site** (checked schedule-appointment, patient-portal, bill-pay, patient-center/new-patients) — only decorative/tracking iframes referenced in JS boilerplate, no actual booking/contact form markup. Proud to Smile should implement real, functioning contact/appointment-request forms since the reference doesn't provide a pattern to literally copy — follow the button/CTA copy and placement, but build genuine form functionality.
- **Primary nav "Doctors", "Find Location", "Patient Portal," and "Schedule Appointment" links are technically broken** on the reference site (missing hostname in href, see Quirks above) — fix these when rebuilding.
- Blog and News are separate WordPress content types with separate index pages (`/blog/`, `/about/news/`) and separate URL namespaces (`/blog/...` vs `/news/...`) — keep them as two distinct collections in the Proud to Smile build, not merged into one.
- Contact information is inconsistent across the reference site (Chandler AZ in copy/titles, Glendale/Tempe AZ in actual footer addresses, "Harrison, OH" in some page titles) — this is a demo-content artifact; use the client's real single-market info for Proud to Smile and pick one consistent city/region.
